Data Machi 並不是一開始就被設計成完整的企業 Agent。它的起點更像是一個能讀取 Google Sheets、協助分析需求工單的工具。隨著使用情境增加，問題也逐漸浮現：資料定義放在 Confluence、專案進度放在 Trello、規範可能藏在 PDF，而使用者的問題常常需要同時參考多個來源。

## 系統如何一步步長大

第一階段，是讓 AI 能讀取結構化資料並回答數字問題。第二階段，是加入文件檢索，讓回答不只包含數字，也能找到定義與背景。第三階段，是讓 AI 自己判斷該使用哪個工具。第四階段，則加入上下文判斷、釐清問題、回答查核、錯誤處理與會議工作流。

整條演進路徑可以簡化成：

```text
Chat → RAG → Tool Use → Agent → Agentic Workflow → Enterprise AI Product
```

## 為什麼這段歷程值得寫？

很多教學會直接展示完成版架構，卻省略真正困難的部分：第一次搜尋找不到怎麼辦？模型沒有呼叫工具怎麼辦？同一問題要不要重新查資料？等待太久如何處理？這些問題才是 Demo 與可使用產品之間的差距。

## 系統定位

Data Machi 更適合被稱為「企業數據與知識工作夥伴」，而不只是 Data Agent。它的價值不在於模擬一位萬能員工，而是把原本分散的知識來源與工作步驟，整理成一條可重複、可驗證的流程。

## 踩坑筆記

系統名稱可以保留親切感，但對外介紹時要清楚說明它能處理什麼、不能處理什麼。Agent 並不代表無所不能，明確邊界反而是企業信任的起點。
