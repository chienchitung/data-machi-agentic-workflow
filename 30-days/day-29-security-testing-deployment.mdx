一個 Agent 在本機能正確回答，不代表它已經適合企業使用。本機環境缺乏真實的多使用者負載、沒有資料隔離的壓力、憑證可以隨意放在設定檔，出錯了重啟一下就好。但正式上線代表的是：真實使用者的資料、真實的安全攻擊面、真實的服務可用性要求。這篇整理企業 Agent 上線前，每個團隊都應該系統性處理的四大面向。

## 一、憑證安全：第一道防線

<Warning>
  API Key 一旦進入 Git 歷史，即使後來刪除了那一行程式碼，只要有人能存取 git log，就能還原出那把金鑰。必須視為已暴露，並立即旋轉所有相關憑證。
</Warning>

### 憑證管理的基本守則

<Steps>
  <Step title="永不硬編碼（No Hardcoding）">
    所有 API Key、Service Account 憑證、資料庫密碼都必須透過環境變數或 Secret Manager 提供，絕不寫入程式碼。

    ```python
    # 錯誤
    OPENAI_API_KEY = "sk-proj-abc123..."

    # 正確
    import os
    OPENAI_API_KEY = os.environ.get("OPENAI_API_KEY")
    if not OPENAI_API_KEY:
        raise EnvironmentError("OPENAI_API_KEY 未設定")
    ```
  </Step>
  <Step title="加入 .gitignore 防護">
    ```gitignore
    .env
    .env.local
    .env.production
    **/service-account.json
    **/credentials.json
    **/*.pem
    **/*.key
    ```
  </Step>
  <Step title="使用 Secret Manager 管理生產環境憑證">
    正式環境建議採用 AWS Secrets Manager、GCP Secret Manager 或 Azure Key Vault，並設定最小權限、定期輪換與存取稽核。
  </Step>
</Steps>

```yaml
services:
  - type: web
    name: my-agent-backend
    env: python
    envVars:
      - key: OPENAI_API_KEY
        sync: false
      - key: GROQ_API_KEY
        sync: false
      - key: DATABASE_URL
        fromDatabase:
          name: my-agent-db
          property: connectionString
```

### 其他安全攻擊面

<CardGroup cols={2}>
  <Card title="跨網域設定（CORS）" icon="globe">
    正式環境不應設定為 `*`，必須明確列出允許的 Origin，並驗證所有跨域請求 Token。
  </Card>

  <Card title="輸入驗證" icon="shield">
    使用者輸入應進行長度限制與基本過濾，降低 Prompt Injection 與異常輸入風險。
  </Card>

  <Card title="錯誤訊息不暴露內部資訊" icon="eye-slash">
    對外錯誤不應包含 stack trace、資料庫結構、API 路由或內部 IP。
  </Card>

  <Card title="資料傳輸加密" icon="lock">
    所有 API 通訊必須使用 HTTPS，並確保 TLS 憑證自動更新。
  </Card>
</CardGroup>

## 二、測試策略：超越人工聊天測試

<Accordion title="Smoke Tests：確認基本功能不壞掉">
  ```python
  import pytest
  import httpx

  BASE_URL = "http://localhost:8000"

  @pytest.mark.asyncio
  async def test_health_check():
      async with httpx.AsyncClient() as client:
          response = await client.get(f"{BASE_URL}/health")
      assert response.status_code == 200

  @pytest.mark.asyncio
  async def test_chat_endpoint_responds():
      async with httpx.AsyncClient(timeout=30) as client:
          response = await client.post(
              f"{BASE_URL}/api/chat",
              json={"message": "你好", "session_id": "smoke-test-001"}
          )
      assert response.status_code == 200
      assert len(response.json()["content"]) > 0
  ```
</Accordion>

<Accordion title="路由與工具呼叫測試">
  ```python
  @pytest.mark.asyncio
  ```

## 三、Debug 面板與可觀測性

<Note>
  可觀測性是指系統能讓開發者在不修改程式碼的情況下，理解任意時刻的內部狀態。對 LLM 行為不確定的 Agent 系統尤其重要。
</Note>

```typescript
interface DebugTrace {
  sessionId: string;
  turn: number;
  timestamp: string;
  contextDecision: {
    type: "RAG" | "TOOL" | "GENERAL" | "CLARIFY";
    reasoning: string;
    confidence: number;
  };
  toolsCalled: Array<{
    name: string;
    input: Record<string, unknown>;
    output: string;
    latencyMs: number;
  }>;
  llmCalls: Array<{
    model: string;
    promptTokens: number;
    completionTokens: number;
    latencyMs: number;
    cost: number;
  }>;
  totalLatencyMs: number;
  totalCost: number;
}
```

正式環境中，這些資訊應寫入結構化日誌供後台查詢，但不直接顯示給一般使用者。

## 四、部署架構與資料持久化

```text
前端（Next.js）→ Vercel
後端（FastAPI）→ Render / Railway / Fly.io
資料庫（PostgreSQL）→ Supabase / Railway / 雲端 RDS
向量資料庫（FAISS / Chroma / pgvector）→ 持久化儲存
```

<Warning>
  暫存磁碟不等於持久儲存。許多雲端服務在重新部署或重啟後，暫存磁碟資料會消失。對話歷史、PDF 索引與會議記錄必須有明確的持久化策略。
</Warning>

| 資料類型 | 建議儲存方式 |
| --- | --- |
| 對話歷史 | PostgreSQL |
| PDF 原始檔案 | Object Storage（S3 / GCS / R2） |
| 向量索引 | pgvector 或持久化磁碟 |
| 會議記錄 | PostgreSQL |
| Session Token | Redis 或資料庫 |
| 使用者設定 | PostgreSQL |
