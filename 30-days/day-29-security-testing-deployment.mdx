一個 Agent 在本機可以回答，不代表它已經適合企業使用。正式上線前，還要處理憑證、安全、資料保存、測試、部署與可觀測性。

## 憑證不能放進程式碼

API Key、Service Account 與內部系統 Token 應透過環境變數或 Secret Manager 提供。即使檔案後來從 repo 刪除，只要曾經進入 Git 歷史，就必須視為已暴露並旋轉金鑰。

## 測試不能只靠人工聊天

Agent 需要測試的不只是「答案好不好」，還包括：上下文路由是否正確、工具是否真的被呼叫、錯誤是否正確分類、PDF 是否能搜尋、會議輸出 schema 是否穩定，以及前端改動是否破壞原有功能。

Data Machi 已加入後端 smoke tests、前端 lint、production build 與自動化測試。Debug 面板則用來查看每輪的上下文判斷、工具呼叫、耗時與 token metadata，但正式環境不顯示。

## 部署與資料保存

前端與後端可以分別部署到 Vercel 與 Render。對話、會議、PDF 索引與快取若只存在暫存磁碟，服務重啟後就會消失，因此正式環境需要持久化儲存策略。

## 踩坑筆記

安全修正不能只看目前程式碼。憑證外洩、跨網域設定過寬、錯誤訊息暴露內部資訊，都需要從整個系統與歷史紀錄檢查。
