ReAct 是 Reasoning and Acting 的縮寫，核心概念是讓模型在推理與行動之間交替。

一個典型流程是：理解問題、選擇工具、觀察工具結果，再決定是否需要下一個行動。對使用者來說，它看起來像 AI「會自己處理」，實際上是模型與工具在一個受控循環中反覆交接。

## 一個簡單例子

使用者問：「今年哪個市場的需求工單最多？」

- Agent 判斷需要資料工具。
- Tool 回傳工作表結果。
- Agent 觀察資料中是否包含完整年度與市場欄位。
- 若資料足夠，整理答案；若不夠，補查或提出釐清。

## 為什麼 Observation 很重要？

沒有觀察階段，模型只會在執行前規劃一次。加入工具結果後重新判斷，才能處理「查無資料」「找到多筆同名卡片」或「欄位不存在」等真實情況。

## Data Machi 實戰

Coordinator 的 Graph 會在 Agent 與 Action 節點之間循環。模型發出工具呼叫後，Action 執行，再把 ToolMessage 送回 Agent。直到模型產生最終回答或達到停止條件。

## 踩坑筆記

循環必須有上限。若工具一直失敗、模型反覆搜尋或不停改寫查詢，就可能造成高延遲與成本。Agentic 不等於無限制嘗試。
