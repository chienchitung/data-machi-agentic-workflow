企業 AI 系統最危險的失敗，不是回答「我不知道」，而是用非常有自信的語氣，說出一個看起來合理但實際上錯誤的數字、日期或進度。真正可靠的企業 Agent，必須知道何時停下來問清楚、何時重新查核，以及如何讓幻覺無處生根。

## 什麼是幻覺，為什麼會發生？

語言模型的任務是預測下一個最可能的 Token。當沒有足夠真實資料支撐時，它仍可能生成流暢合理、但實際錯誤的內容。

```text
數字捏造：「這個季度的轉換率是 23.7%」
日期錯誤：「這個功能在 2024 年 3 月上線」
名稱混淆：「負責這個專案的是 Alex Chen」
邏輯填補：「延遲是因為跨部門溝通問題」
```

<Warning>
  分析可以提出假設，但必須明確標記為「待驗證假設」，不能用事實陳述的方式呈現。
</Warning>

## 何時應該先釐清？

<Steps>
  <Step title="識別模糊的必要條件">
    若使用者只說「幫我做分析報告」，卻沒有資料來源、時間範圍與分析對象，系統缺乏執行所需的關鍵條件。
  </Step>
  <Step title="找出最關鍵的一個問題">
    不要一次詢問所有未知條件。應識別「如果這個條件錯了，一切都白費」的最關鍵問題。
  </Step>
  <Step title="提供具體選項">
    與其問「你想要哪個時間範圍？」，不如問「你是指 2024 Q3，還是最近 90 天？」
  </Step>
</Steps>

```text
使用者：「幫我整理最近的銷售狀況」
→ 釐清：「你是指本月整體銷售額，還是特定產品線？」

使用者：「查一下那個專案的進度」
→ 釐清：「你是指 Project Atlas 還是 Project Nova？」
```

## 何時不應該釐清？

<Note>
  當使用者只是延續前文，而且指稱物在對話中已清楚，就不應重新詢問已知條件。例如已確認討論的是亞太市場 Q3 資料，使用者說「整理成表格」，直接轉換即可。
</Note>

## 什麼是 Verification Request？

<CardGroup cols={2}>
  <Card title="Verification 訊號" icon="magnifying-glass">
    「你確定嗎？」「重新確認一下」「這個數字好像不對」「再查一次」「我剛更新資料」
  </Card>

  <Card title="正確處理方式" icon="check">
    忽略可能過時的先前結果，重新呼叫原始工具，取得最新資料後比較新舊差異。
  </Card>
</CardGroup>

```python
def handle_verification_request(state: AgentState) -> AgentState:
    state["tool_context_valid"] = False
    previous_result = state.get("prior_tool_context", {})
    new_result = force_fresh_tool_call(state)

    if results_differ(previous_result, new_result):
        return format_diff_response(previous_result, new_result)
    return format_confirmed_response(new_result)
```

## 零幻覺架構的設計原則

<Steps>
  <Step title="所有事實都必須可追溯">
    數字、日期、人名、專案名稱與規定條文，都必須對應特定工具查詢結果。
  </Step>
  <Step title="找不到就說找不到">
    工具無結果時，明確說明「在指定資料來源中找不到相關資料」，不要用常識補空白。
  </Step>
  <Step title="跨來源都找不到，不能靠猜">
    內部縮寫或專案代號沒有明確對照時，不得自行假設。
  </Step>
  <Step title="假設要標記為假設">
    可能原因與潛在風險可以提出，但要與事實陳述清楚區隔。
  </Step>
</Steps>

<Info>
  Data Machi 的設計原則：數字、日期、名稱與規定，都必須能追溯到工具結果。工具找不到時，就明確說明資料不足。
</Info>

## 釐清與幻覺防護範例

```text
使用者：「ATL 這個月的進度怎麼樣？」

錯誤：自行猜 ATL 的全名與完成率。

正確：
「我在 Trello 和 Confluence 找到兩個名為 ATL 的項目：
1. ATL-2024：亞太物流改善計畫
2. Atlantic Region Q4 Campaign
你想查詢哪一個？」
```

```text
使用者：「上週五的 Daily Standup 說了什麼？」

正確：
「我搜尋了上週五的會議記錄，沒有找到相關紀錄。
請問記錄是否存放在其他位置？」
```

## 釐清問題的設計技巧

<Accordion title="只問最關鍵的一個問題">
  一次問太多問題會讓使用者不耐煩，也可能讓對話失焦。
</Accordion>

<Accordion title="提供具體選項">
  具體選項能降低使用者思考成本，也讓 Agent 更容易準確理解意圖。
</Accordion>

<Accordion title="說明為什麼需要釐清">
  「我找到兩個同名專案」比單純問「你說的是什麼？」更透明。
</Accordion>

<Accordion title="釐清後立即行動">
  使用者回答後，不要再問一次確認，應直接執行查詢。
</Accordion>

<Info>
  今天只要記住一件事：可靠的 Agent 不只知道如何回答，也知道何時應該停下來問與重新查。
</Info>
