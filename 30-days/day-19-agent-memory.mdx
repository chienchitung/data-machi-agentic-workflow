多輪對話中，Agent 不只要記得使用者說過什麼，也要分辨哪些內容仍然可信、哪些資料需要重新查詢。

## 三種常見記憶

- **近期對話**：保留最近幾輪訊息，處理代名詞與追問。
- **摘要記憶**：把較早內容壓縮，避免上下文無限成長。
- **工具結果記憶**：保存先前查到的資料，供後續整理與比較。

Data Machi 會保留最近的可見對話，較早內容則整理成 Conversation Memory。工具查詢結果另外保存成 Prior Tool Context，避免只依賴模型上一輪的文字回答。

## 為什麼不能全部保留？

對話愈長，Token 成本與誤解風險愈高。模型可能抓到很久以前的條件，忽略最新需求。因此記憶不是愈多愈好，而是要保留對當前任務真正有用的資訊。

## 何時應重新查？

若使用者只是要求改寫、補充說明或轉成表格，可以沿用資料；若要求最新、全部、重新核對或新增篩選條件，就應重新呼叫工具。

## 踩坑筆記

模型生成的摘要不能完全取代原始 Tool Result。涉及數字與事實時，最好保留可追溯的工具上下文，避免摘要過程漏掉條件。
